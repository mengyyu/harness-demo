## 7. Agent 架构

### 7.1 运行时选择（冲突点，见附录 C1）

- **LangGraph 为主运行时**：现有 loop.py 已是真实 StateGraph 且全链路可跑，重构节点即可满足需求。
- **DeepAgents 保留为可选路径**：factory.py 继续存在，`create_deep_agent` 可用时通过同一 `AgentRuntime` 接口暴露；默认关闭。

### 7.2 状态与图重构

```python
# 现有 AgentState（loop.py:22-51）扩展为：
class AgentState(TypedDict):
    run_id: str              # 新增：统一 run_id
    agent_id: str            # 新增
    user_id: str
    customer_id: str | None  # 新增：客户隔离维度
    input: Any
    intent: str | None
    intent_confidence: float
    messages: list           # 新增：对话历史
    context: dict            # 新增：上下文
    memories: list
    selected_skills: list    # 新增：planner 输出

    tool_calls: list         # 新增

    status: str
    final_answer: str | None
    error: str | None
```

节点重构（现有 7 节点 → 目标 10 节点，全部可达）：

```
intent_detection → context_loader → memory_loader → planner
      → skill_selector → skill_executor → tool_executor
      → observation → decision ──(继续)──→ skill_executor (循环)
                        └──(结束)──→ final_response
```

- 删除/打通现有死节点 `reflect`（合并进 `observation`）
- `execute_node` 中硬编码的意图→Skill 派发、客户 ID 映射全部移除，改由 `planner` + `skill_selector` 通过 `SkillRegistry` 动态选择
- `decision` 实现现有 `should_continue` 语义 + 超时 + 迭代上限

### 7.3 Loop 控制（AgentConfig）

```python
class AgentConfig(BaseModel):
    max_iterations: int = 10      # 替代现有 AGENT_MAX_LOOPS
    timeout: float = 120          # asyncio.timeout 包裹整轮

```

落库字段：`agents.max_iterations/timeout/retry_count/...`，运行时从 DB 读取，**不再读全局 settings**。

### 7.4 多 Agent
